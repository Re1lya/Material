## 6. 数据管线自动化路线

两条链路必须分开：

```text
代码发布：Gitea push/PR -> K12 Tekton CI -> AMD64 image -> Artifact Keeper digest
          -> Gitea 配置 PR -> 人工 Argo Sync -> Dagster definitions 更新

数据运行：Backstage 受限表单 -> CPU staging run request -> 已审核 Dagster job
          -> Dagster run history / output summary -> Backstage 只读展示
```

源码 push 不应自动处理真实数据，更不能自动申请 NPU；Backstage 数据运行也不能构建任意源码或
直接写 Kubernetes。第一版只允许 `cpu-staging-v1`、固定 staging S3 prefix 和小批量 CPU smoke。

当前完成：

- 固定 upstream commit；
- 离线 AMD64 安全 control-plane 镜像及不可变 digest；
- 11-object CPU-only foundation 源码与本地 render/client dry-run；
- Backstage 数据管线页面/API 的本地实现；
- Git-only `DataPipelineRunRequest` schema/validator 的本地实现。

当前未完成：

- 新 namespace、20Gi Retain PV/PVC、只读 imagePull Secret；
- prefix-scoped、非 root MinIO identity；
- K12 Gitea 源码仓库和专用 Tekton EventListener/Pipeline；
- 可执行且完全不导入 Ray/NPU resource 的 `cpu-staging-v1`；
- Dagster foundation 生产 apply、健康和 Backstage 真实状态验收；
- 后续任何 Ray/NPU 阶段。

## 7. 自动化身份

已记录的工作流身份：

- Gitea `model-platform-writer`：仅 `gitadmin/model-platform-config` write，用于受限 GitOps 请求；
- Artifact Keeper `svc-k12-data-pipeline-publisher`：仅 Docker format 的 `container-images`
  `read,write`，服务器端 root-only Docker config；
- 各运行时、CI 和镜像拉取身份继续按一个工作流一个 Secret/Token 管理。

用户另行要求创建“供 Agent 发布使用”的 Gitea 与 Artifact Keeper release bot。该通用身份截至
本文时间**尚未创建**：不得把现有 workflow-specific writer/publisher 擅自扩权或共享。创建前需
确认 Gitea 管理员身份及精确仓库范围；Artifact Keeper 建议仅 `container-images` read/write，
不授予 delete/admin。文档只能记录账号名、权限、Secret/受控凭据路径和轮换日期，不得记录
密码或 Token 值。

5. 增加并 smoke `cpu-staging-v1` 后，再启用 Backstage 运行请求与 Dagster runs 监控。

## 9. 禁止事项

- 不要打印或提交 Secret、Token、密码、Docker config、kubeconfig。
